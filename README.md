# personal-site-2026

Scott Robertson's portfolio: a sideways swipe feed of interactive logo "labs". Plain static files, no build.

```
npm run sync     # copy the labs in from workspace/labs (or: node scripts/sync-labs.mjs <labs folder>)
npm run serve    # http://localhost:8123/  (the workspace: http://localhost:8123/workspace/labs/goop.html etc.)
```

- `workspace/`: Scott's workspace, where the labs are developed: `labs/` (lab pages, `shared/`, `notes/` with the old versions), `ideation/`, `brand/`. Kept in the repo but **not part of the website**: `netlify.toml` answers 404 for `/workspace/*`, so it's only browsable locally through `npm run serve`. (Before 2026-10-29 this lived in a separate folder, `../sr-personal-2026`.)

- `index.html`, `site/`: the feed. `site/config.js` holds the order, the start toy, the toys too heavy to preload, and the artist card.
- `labs/`: **generated** by `npm run sync`, never edited by hand. The labs are developed in `workspace/labs`; the sync copies the lab pages, `shared/`, `notes/behind-the-scenes.md` and `notes/versions/`, writes `labs/manifest.js`, and adds one `<script>` tag to each lab page for the embed hooks.
- `embed/lab-embed.js`: the embed hooks. `lab.html?embed=1` shows the stage only; the feed plays, pauses and snapshots it by postMessage. Without `?embed` it does nothing.

URLs: `/lab/sand/` opens the feed on a toy, and its link preview (Messages, Slack and so on) is that toy's square card from `share/`; the feed keeps the address bar on the toy on screen, so a shared link previews what was being looked at. `npm run share [slug ...]` remakes the cards (`scripts/share-card.html`, timed by `SHARE_AT` in `site/config.js`) and the `lab/<slug>/` pages, which are copies of `index.html` (`-- --pages` rewrites only the pages: run that after a sync or an edit to `index.html`). The old `/#sand` still opens the feed on a toy; `/#prism/glass_diamond~pal_reef` also carries a lab's settings code into the toy and its "Change This" link. `?stats` shows a frame-time readout; `?solo` turns off preloading (for measuring). Moves between toys play a WebGL ripple (`site/transition.js`); `?fx=off` keeps the plain slide, which reduced motion and browsers without WebGL also get. The ripple plays over stills: both toys hold still under it and the incoming one starts as it lifts. Swiping has two tiers: until you touch the toy on screen a swipe moves on easily; once you have, leaving (from the edge zones too) takes a long pull (45% of the screen) that grows a bubble of the toy itself, and letting go short shrinks it back. On a tall screen two quiet chevrons mark where a swipe starts (the foot of the top edge zone, and over the caption); they light up during a swipe. Neighbours load one at a time (the next toy, then the one before), each only once the toy on screen and the neighbour before it have drawn, and none while someone is touching the toy on screen (1.5 s of quiet first): every toy shares the page's main thread, and starting one up holds it for a second or more on a phone. A toy listed in `NO_PRELOAD` (`site/config.js`, empty now: over HTTPS an iPhone starts every toy within 0.7 s) never preloads; it loads when landed on, under the spinner. Resting neighbours are parked on screen, under the toy on screen, and go back beside it only when a move starts (Safari barely runs animation frames in an iframe outside the viewport, so a neighbour waiting beside the screen didn't draw until swiped into view); in the feed a lab also always reads as on screen to its own IntersectionObserver. `?trace` records a run-through on a real device and sends it to the dev server (`traces/`). Past each chevron (above the top one, below the bottom one) a small pie fills while that neighbour loads (an empty ring while it waits its turn; neither shows for the first half second) and fades once it's ready, and the chevron nudges the way it points now and then until it is. The pie's pace is a guess: the toy's last load on this device, or its cold time in `site/load-times.js` scaled by how this device has done on the toys it has loaded (`npm run load-times [slug ...]` remakes the table; re-run it when a lab is added or changes its start-up). During a drag the chevron, ring and slot stay on the centre line; reaching the ring flares it together with the ripple's front, then it fades, and pulling back short fades it in again; a spinner sits over the toy on screen while it hasn't drawn or hasn't started moving, with a pie inside it filling over the same guess while it loads or compiles (Goop's twenty-odd seconds read as a wait with an end). Both animate on transforms only, so they keep turning through a stall. While a toy loads, its slide (and the ripple) shows the toy's first frame from `posters/first/` (`npm run posters -- --first` remakes them), falling back to the breathing mark until the image has loaded.
